<h2>Claude订阅住宅IP池的调度逻辑：池子规模、分配策略与命中率</h2>

<p>Claude订阅住宅IP池，卖的是一个池子而不是一条线。理解池子，关键不在总数，而在调度：地址怎么分配、什么时候回收、重复率多高。这三点决定了你实际拿到的是什么样的体验。</p>

<p>先看规模。池子大，重复率低，短时间内不容易撞回用过的地址。但规模大不等于质量好，一个几万条的池子里如果大半是不可用的段，实际可用量可能只有零头。</p>

<p>再看分配策略。常见的有轮询、随机、按会话粘性。轮询最均匀但可能把同一段连着给你；随机重复率高；按会话粘性体验最好，但需要服务方做状态管理。</p>

<p>然后看回收机制。地址用完后多久回到池子、回到池子后多久再分配给别人。回收太快，同一地址会被频繁复用，表现变差；回收太慢，池子的有效容量下降。</p>

<p>最后看命中率。你要的地区在池子里占多少比例，直接决定请求落空的概率。宣称全球覆盖但目标地区占比很低的池子，用起来会非常难受。</p>

<p>把这四点问清楚，池子的实际能力就基本清楚了。只问总数，等于只问了一家餐厅有多少张桌子，却不知道翻台率和订位规则。</p>

<p>还有一个指标值得关注：池子的地区分布是否均衡。有的池子在少数几个地区堆了大量地址，其余地区只有零星几条，业务需要长尾地区时就会频繁失败。</p>

<p>关于会话粘性，池子方案和单线方案的要求不一样。池子里的粘性通常是限时的，超过时限仍会换。业务的会话长度要小于这个时限，否则中途必断。</p>

<p>成本上，池子通常按用量计费，用多少算多少。这对波动大的业务友好，但对稳定高用量不一定便宜。做预算时按峰值月算，别按平均月算。</p>

<p>还有一个容易被忽略的点：池子里的地址质量是分布的。同一个池子里，有的段很好，有的段很差。如果分配策略是纯随机，你拿到什么全看运气。这时候能不能指定或排除某些段，就成了关键能力。</p>

<p>如果业务量大，建议和服务方确认是否能提供用量与失败的明细。有明细才能定位是池子的问题还是自己用法的问题。</p>

<p>最后，池子方案特别需要日志。哪次请求走了哪个出口、结果如何，必须可查。没有日志，出问题只能整体重跑，成本极高。</p>
